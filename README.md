# Breast Cancer Classification: логистическая регрессия с нуля

Диагностика рака молочной железы по 30 числовым признакам (датасет `load_breast_cancer` из scikit-learn, 569 пациентов). Логистическая регрессия с L2-регуляризацией и мини-батч SGD реализована на чистом NumPy в стиле scikit-learn (`fit` / `predict` / `predict_proba`, совместима с `Pipeline` и кросс-валидацией).

## Результаты

Положительный класс — злокачественная опухоль. В задаче диагностики важнее всего не пропустить больного, поэтому главная метрика — recall, а для выбора гиперпараметров используется F1.

| Модель (тест, 114 пациентов) | Recall | Precision | F1 |
|---|---|---|---|
| SGD-логрег с нуля | 0.952 | 0.976 | 0.964 |
| `LogisticRegression` из sklearn (эталон) | 0.952 | 0.976 | 0.964 |

Из 42 злокачественных опухолей пропущено 2, ложных тревог 1 (из 72 здоровых). Выборка маленькая, поэтому одна ошибка меняет recall примерно на 2.4 п. п.

## Главные выводы

- **Метки классов важны.** В датасете `0` — злокачественная опухоль, а метрики sklearn по умолчанию считаются по классу `1`. После инверсии меток `recall` означает «долю найденных опухолей». Пример: сильно регуляризованная модель выглядит прилично по метрике для доброкачественного класса (F1 0.82), но по злокачественному классу F1 всего 0.44.
- **Расхождение обучения** определяется произведением `lr · alpha`: регуляризация умножает веса на `(1 − lr·alpha)`, поэтому при `lr · alpha > 2` веса растут экспоненциально и случается overflow. Большой `lr` сам по себе модель не ломает: градиент логистической потери ограничен, а шум мини-батчей только ухудшает сходимость.
- **Регуляризация на этих данных качество не улучшает**: признаков мало относительно числа объектов, а классы почти линейно разделимы. При росте `alpha` precision растёт, но recall падает, что для медицинской задачи невыгодно.
- **KFold против ShuffleSplit.** При 100 повторениях кросс-валидации дисперсия оценки F1 у `ShuffleSplit` примерно в 2.8 раза больше, чем у `KFold` (std 0.0094 против 0.0057), потому что в `KFold` каждый объект попадает в валидацию ровно один раз.
- **Порог классификации** можно снизить, чтобы увеличить recall ценой precision (на out-of-fold предсказаниях при пороге 0.3 recall вырастает с 0.953 до 0.965, при 0.1 до 0.982).
- Все гиперпараметры подбираются кросс-валидацией на обучающей выборке, а тест используется один раз в конце.

## Что внутри

```
.
├── breast_cancer_logistic_regression.ipynb   # реализация, эксперименты, выводы
├── requirements.txt
└── .gitignore
```

Основной класс — `SGDLogisticRegression` (гиперпараметры: `alpha`, `lr`, `max_iter`, `batch_size`, `fit_intercept`, `random_state`). Он выдаёт предупреждение, если `lr · alpha ≥ 2`.

## Как запустить

```bash
pip install -r requirements.txt
jupyter notebook breast_cancer_logistic_regression.ipynb
```

Данные загружаются из scikit-learn автоматически. Все случайные процессы зафиксированы (`SEED = 42`), поэтому результаты воспроизводятся. Полный запуск занимает около двух минут.

## Что можно улучшить

- использовать `StratifiedKFold` и подбирать `lr` и `alpha` совместно через `GridSearchCV`;
- добавить затухание шага и критерий остановки по сходимости;
- подбирать порог под требуемый уровень recall;
- сравнить с другими моделями (SVM, градиентный бустинг) и проверить калибровку вероятностей.
